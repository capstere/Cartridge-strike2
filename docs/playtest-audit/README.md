# Cartridge-Strike 2 playtest audit

9 November 2026 · Published Floor 5 · Compared with main at `75e25ce`

The playable core held up through a complete six-round Classic match, an Endless death and respawn, repeated starts, real mouse input and simulated touch. The largest regressions were at the boundaries of a match. An early Start click could disappear, a failed launch could trap the player under a stack trace, and the results screen could reopen over the lobby. The changes in this branch address those failures. Physical-phone performance and audio quality still need a device session.

The November 10 follow-up verified both objective routes, spectator cycling and saved-character recovery on Pages. [Seeds, screenshots and reproduction](november-10/README.md)

## Architecture and performance

The root is a static GitHub Pages redirect with `.nojekyll`. The FPS HTML owns the lobby and overlays. ES modules use a local import map for Three.js r180, vendored Yuka supports AI and steering, and the level manifest selects the 1.76 MB prepared Floor 5 JSON. The simulation, collision, navigation and economy are separate from rendering and DOM updates. The default game uses approved model/animation libraries and reusable level-build modules under `furniture-editor/`. Saved characters are browser-local. The PR is confined to the FPS-only repository. There are no gameplay data, original asset or level geometry changes. [Entry](../../index.html) · [Level manifest](../../levels/manifest.json) · [Game](../../src/fps/game.mjs) · [Navigation](../../src/fps/navigation.mjs) · [Renderer](../../src/fps/render.mjs)

On a cold local main run, Resource Timing reported 250 resources and 23,524,606 transferred bytes by the sampled mobile gameplay frame. One elevator view produced 217 draw calls and 194,530 triangles. A different 932 px Endless view on the branch produced 747 calls and 398,690 triangles. The cameras, actor states and modes differ, so these numbers describe scene cost and cannot measure a branch regression. Software rendering on a shared host is unsuitable for estimating a player's hardware FPS.

A second cold branch run at 844×390 reached DOMContentLoaded in 3.17 s and exposed the ready engine at 24.97 s. The timing buffer contained 263 resource entries and 37,620,604 transferred bytes by readiness. The largest were the 10.18 MB business-character GLB, a 2.46 MB fabric normal map and two operator GLBs at 2.13 and 1.98 MB. These are local HTTP transfer sizes, including timing overhead. They are not production CDN downloads.

For the realtime sample, the browser launched default Floor 5 in Endless as Analysts with the original operator and default mobile low settings. The local client sampled requestAnimationFrame timestamps and the game's Three.js draw counter without moving the camera. The return path used the existing in-page menu routine. The host used CPU-based WebGL. Later samples shared resources with other test work.

| Launch | Inter-frame samples | Median | p95 | Draw calls per frame | Three.js geometries / textures |
| --- | ---: | ---: | ---: | ---: | ---: |
| First | 16 | 1,800 ms | 7,716 ms | 2,256–2,284 | 752 / 204 |
| Second | 8 | 1,833 ms | 3,767 ms | 2,251–2,269 | 752 / 204 |
| Third | 8 | 2,883 ms | 3,933 ms | 2,255–2,270 | 752 / 204 |

All three samples had ten actors. GPU-resource counts stayed level across these three launches. The small samples include startup work, and p95 for eight frames is the slowest observed frame. Hardware measurements and a longer session are needed to distinguish shader compilation, CPU submission, actor rendering and GPU fill cost.

The main renderer and lobby preview have separate frame schedulers. The preview stops scheduling when hidden or covered, and the game render budget reduces rendering behind modals. The normal render loop keeps scheduling callbacks to assess its budget. Renderer state is reused across matches, transient effects and game audio reset on transitions, and non-persisted page exits trigger renderer disposal. These are source-level observations. No long-duration heap, native GPU allocation, or event-listener leak conclusion follows from them. ## Reproduction commands

The Node suite passed 158/158, and the manifest and published-map door checks passed. The standalone launch regression passed with the controller, engine and font held, including a real retry into gameplay and the post-match return. Earlier browser runs hit automation timeouts on the shared software renderer. One timed out tapping pause in the original mobile smoke. The final 844×390 mobile smoke passed, including immediate manual firing after the settings change. A cold default-graphics 1280×720 desktop smoke also timed out waiting 180 s for engine readiness on the shared software renderer. The same default-graphics smoke passed in isolation with one lock request, no mobile overlay and a live buy phase. Its lock request is stubbed by the repository test. The separate lower-graphics desktop journey acquired real mouse lock and completed the match. Physical hardware startup time remains open.

Run from the repository root with Node. For browser runs, install Playwright Core and Chromium in the environment used by the repository's existing browser scripts. Serve the repository with `python3 -m http.server 8765` in another terminal.

```sh
node --experimental-loader ./tools/vendor-three-test-loader.mjs --test src/fps/*.test.mjs tools/*.test.mjs
node tools/verify-owner-runtime.mjs
node --experimental-loader ./tools/vendor-three-test-loader.mjs tools/owner-door-traversal.mjs --prepared
node tools/match-flow-browser.mjs
node tools/mobile-smoke.cjs
```
