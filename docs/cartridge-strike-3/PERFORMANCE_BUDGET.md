# Performance and reproducible measurement

Historical evidence: handover PR45 eight CI jobs/258 FPS/53 server tests reported. docs/playtest-audit/QUALITY_AUDIT_2026-11-22.md identified pathfinding-dominated slow ticks and mitigated room-creation pause. docs/multiplayer/compact-arena/README.md and evidence show historical tests; emulated mobile is not physical. No fresh benchmark in preparation. CS3-00 records baseline and exact methodology before optimizing.

| Area | Measure | Initial acceptance target (provisional, refine by baseline) |
| --- | --- | --- |
| Desktop client | p50/p95/p99 frame time, >50ms stalls, input to first visible frame, draw calls, GPU/CPU | capable hardware near 60 FPS (16.7ms median target); no repeatable p95/p99 regression beyond measurement variation; stable quality setting |
| Mobile client | same, physical iPhone/Android plus emulated 844x390/932x430, memory, touch response, thermal | aim stable 30+ FPS low (33.3ms median), capable phones 60; do not hide degraded graphics or untested device |
| Pi server | tick execution AND interval p50/p95/p99/max, stalls >16.7ms, bot navigation cost, CPU RSS heap, GC | 60Hz simulation, p95 within 16.7ms work budget; improve tail and room creation spikes relative to same baseline, no reduced actor count/rules |
| Network | bytes/s, RTT, prediction corrections, input-confirmed shot latency, reconnect success | no reproducible material regression at same RTT/loss; bounded queues; preserve contracts |
| Startup | cold/warm first menu, map ready, join to playable, shader warmup, bytes | improve or justify overhead; avoid first-seconds stutter and repeated loading |
| Lifecycle | 20+ match/map switches, join/leave/reconnect, preview cleanup, concurrent rooms | no monotonic retained object/heap growth after settle; no orphan sockets, listeners, GPU assets; no cross-room stalling |

Use identical hardware, browser, quality/resolution, seed, map, player/bot count, warm-up and sample windows, 3+ repeats where practical. Record build SHA, renderer info, software acceleration, thermal/CPU clocks, elapsed time, p50/p95/p99/max and count of slow frames/ticks. Separate instrumentation overhead, real client GPU vs Pi simulation, network latency vs render delay. Use existing tools/measured-simulation.mjs, measured-floor5-profile.mjs, network-load.mjs, network-load-server.mjs, network-room-startup.mjs, network-delay.mjs, asset-memory-profile.mjs, mobile-reliability-browser.mjs and documented scripts. Run one heavy Pi task at a time, staging distinct port/state; do not benchmark by disrupting real matches. Use cached route templates, bounded navigation budgets and distributed searches with correctness tests. Adopt instancing, LOD, shader prep, adaptive resolution, pooling and caching only with before/after evidence. No weakening thresholds/tests or feature deletion solely to meet metrics. Candidate quality profiles explicit. Hardware constraints and physical-device gaps reported in final release evidence.
