# FPS feel, Rush, characters and combat

## Required vertical slice
Compare stock CS2, in-repo standalone Frontline and candidate under the same hardware/browser and representative settings. Capture first-person view, input-to-visible response, frame stalls and audio onset for one existing rifle and pistol. Evaluate playability qualitatively without claiming a benchmark before running it. Use existing CR4 as proposed first rifle and P9 pistol, then all supported held items. Reuse existing hand improvements (docs/view-arms/README.md), recoil and motion springs before replacing them.

## Rush mandatory
Reference 5.6.0 has actual sprint logic: 07c-controller.js ctlMove checks intent, forward motion, incompatibilities, then smooths arms.sprintW; ctlWeapon blocks firing until sprint exits. 08-player.js routes keyboard/touch/pad run and firing interrupts sprint, updates footstep bob and calls updateViewmodel. 06-weapons.js updateViewmodel (405) springs VM.sprint and blends pose, reduces effective sprint during choreography; 06c-models.js pistolRunPose (638) and elbow/left-hand behavior. The reference code tilts long guns down/side, while screenshot shows a raised gun during countdown; do not assert that identical screenshot is sprint. Reproduce closest intended visible lifted/angled pose through original compatible tuning. Compare normal running vs sprint and record video. 
- Explicit sprint intent in shared input and server movement; do not relabel current ordinary run as sprint. Proposed forward threshold and speed tuning based on reference/baseline, no hardcoded copied speed before collision tests.
- Shared movement state: grounded walk/run/crouch/sneak, sprint, slide, airborne, disabled; action compatibility (sprint begins only on legal motion, fire/ADS exits, reload/inspect/switch/throw transitions follow one priority table). Prevent teleport, repeated slide boost, wall penetration, jump exploits and mismatched prediction. State/intent replay at fixed tick.
- Presentation blends actual speed and movement direction, spring to distinct per-weapon sprint pose, weapon-specific two-handed versus pistol/free hand, natural arm/camera bob; reduced motion affects camera only. No snapping, unintended clipping, loose grip or obstructed view; clear ready-to-fire timing; third-person sprint and slide match authoritative state. 
- Move/aim/fire/reload/inspect/crouch/slide/jump/death/respawn/reconnect/match end reset correct pose; support keyboard, mobile, gamepad. Rush ≠ Rage.
- Use action start/end/event ID for reload/switch/shot animation, magazine interaction, weapon moving parts, fingers, recoil recovery, shell and foley. Ammo follows shared authoritative deadline, not frame animation. No duplicate delayed sound or shell events.

## Characters
Keep compatible GLB custom packages and Quaternius rigs. Define canonical animation intent from ARCHITECTURE, build adapters for existing clip names/axes and optional original procedural soldiers. Blend directional walk/run/strafe/backpedal/diagonal, crouch/aim, upper/lower layers, turn in place, ground/air/land, hit reactions, deaths, IK hand/feet. Use licensed/original clips or procedural fallback; existing reference import removed Mixamo clip bank. Retargeting must preserve skin, sleeves/gloves and team identity. LOD/pose caching and disposal. Test 13 held objects plus mission bomb as applicable, male/female, custom imported GLB, dwarf, resident/hostage where affected. Do not change old assets merely for uniform appearance.
Ragdoll is client visual only until a separately reviewed collision contract is approved. Joint hitbox work requires deterministic authoritative pose samples, rewind, hit-zone mapping, collision fairness, high bot load measurements, and same offline/server rule. Current coarse headshot/corpse behavior stays as regression baseline. Inspect all damage paths and dead-body navigation before replacing.
## Audio and feedback
Use shared event IDs and relative time: immediate local cosmetics, confirmed hit/kill, remote spatial sounds, surface steps and reload sequence. Extend active riposte-audio and existing foley; near/far occlusion, ambience, UI/bonus/match cues, channel mix, volume/mute, queue/decode limits; no replay of stale event after unlock/reconnect. Preserve original Preparation and special resident music. Capture real sound and motion together.
## Acceptance
Each weapon's full normal flow plus cancellation in offline and two-client online match; input-to-ready timings and video; no ammo/damage regression; correct crouch/slide/landing, no collisions bypass; frame budget; physical touch status explicit. Fix measured problems, do not just add more systems.
