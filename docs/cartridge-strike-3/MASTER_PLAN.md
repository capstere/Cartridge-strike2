# CS3 — owner requirements and definition of success

## Mission
Make the successor to CS2 a polished, coherent and enjoyable browser FPS, using Riposte as the principal technical and interaction reference. Maximize compatible reuse, not the number of files copied. Preserve the existing repository, production hostname, Pi 5 (16 GB), shared simulation, server-authoritative Colyseus, prediction/reconciliation, lag compensation, family room, original maps, custom characters, Classic/TDM/Endless, zombies and Dansmannen. Preserve the actual current scope of online/offline modes; do not accidentally promise Endless online without implementing it. A backup is sufficient; no permanent second production game is needed.

**English is mandatory at first CS3 release.** All player-facing strings, menus, HUD, subtitles, tutorial/help, settings, errors, loading and lobby, accessibility labels, release notes and server notices must use English by default. Use centralized message keys and English fallback, not hard-coded translated fragments. Historical Swedish documentation is preserved; new CS3 code documentation and agent instructions use English. Never rename persisted IDs merely to translate labels.

## Required workstreams
- Frontend: original cinematic Tactical Industrial visual system inspired by the 16 main screenshots and five recordings; Main, Play, Solo/Friends/Public Matches, map cards, match configuration, roster, readiness, host, class picker, Outfits, Options, What's New, Profile, quick join, fullscreen/PWA. Real previews and meaningful loading/error/empty states. Desktop, landscape mobile, portrait menus and tablets.
- Access: stable family link and remembered authorized session, invitation link/QR and optional short code, reconnect/rematch. Guest solo, optional accounts, persistent profile/avatar/settings/loadouts/statistics and progression; opt-in public matches with appropriate access, moderation and limits.
- Gameplay: immediate feedback, weapon poses/weight/sway, camera springs, ADS, recoil, reload, inspection, switching, fingers/magazines, Rush sprint, slide, crouch, jumping/landing, melee and throwable animations. Preserve simulation truth and weapon balance unless measured intentional changes are documented.
- Characters: directional locomotion, blending, upper/lower body, IK, aim offsets, hit reactions, deaths, visual ragdolls, clothing/equipment, LOD, compatible GLB imports. First-person hands and sleeves match selected avatar. Joint hitboxes are a separate authoritative change, not cosmetic.
- Killstreaks: UAV 3/15s, Rage 5/15s, Immortal 8/8s; manual activation, carry unused charges across death within match, no bonus-generated progress, server verification. See dedicated spec.
- Bots: improve perception, cover, decisions, coordination, movement, obstacle recovery and multilevel routes without replacing useful existing Yuka logic blindly. Keep CPU spikes under control.
- Graphics/maps: reusable geometry, PBR, lighting/shadows, atmosphere, vegetation/water/wind/fabric, props, effects/LOD. Retain Floor 5 and Compact Arena. Investigate all nine source maps; deliver verified compatible maps in order, record genuine blockers with alternatives.
- Audio: positional near/far, footsteps/surfaces, variations, reload foley, ambience, announcements, UI and effects; preserve original music/custom sounds. No late stale playback.
- Match presentation: countdown, respawn, scoreboard, objectives, killfeed, spectator, killcam/final replay, XP, player/weapon levels, challenges, cosmetics, FFA and Domination. Classic purchasing remains authoritative.
- Mobile: simultaneous movement/look/fire, layout editor, size/opacity, saved/importable profiles, ADS/aim assist, auto/manual fire/reload, sprint/slide, bonus buttons, safe areas, gamepad, browser/PWA, iPhone/Android.
- Future expansion: typed/versioned content registries, validation/import/thumbnail tooling for characters, rigs, animations, outfits, weapons, attachments, equipment, bonuses, audio, maps, game modes, bots, UI themes and progression.
- QA: compare actual playable reference and baseline, then implement/test each vertical slice. No placeholders reported as done. Track p50/p95/p99, network/tick/heap/startup, physical device gaps, exact revision and evidence. Keep Pi production stable.

## Release boundaries
Preparation is docs and agent routing only. Owner review must precede implementation. Integrate in a CS3 development branch using focused commits/PRs. Release only after verified staging, migration, backups, rollback rehearsal and idle-room check. The owner does not need to coordinate specialists. See roadmap, gate and acceptance matrix. Prioritize responsiveness and a working complete player flow before content breadth. No feature is waived silently; record unimplemented scope and owner-visible impact.
