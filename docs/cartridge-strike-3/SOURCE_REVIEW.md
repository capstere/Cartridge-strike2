# Riposte source review

The reference contains working first-person animation, weapon choreography, touch controls, menu navigation, map construction and test instruments that CS3 can use. The shortest integration path is to port the component that produces each visible result into its existing CS2 owner. The authoritative game already runs headlessly, and the browser already predicts movement using the same function as the server.

## Reference tests worth porting

The reference's 135 tool files include 81 JavaScript files under `tools/dev/visual/` (including helpers, studies and drafts). They use standalone game globals and a separate harness. Port the measurement/interaction into CS2's normal launch and protocol tests. These fixtures were inspected here, not executed against a CS3 build.

- `course-recharge.js` advances the viewmodel at 60 Hz and projects the muzzle/holder to quantify reticle coverage throughout standing vs running reloads. `recharge.js` samples handling at 120 Hz. `mains.js`, `recul.js`, `sauts.js`, `couteau-main.js` and `marche.js` complement those checks. Keep a video alongside grip/pose metrics; use pistol and long-gun silhouettes, the full transition and a moving viewpoint.
- `tactile.js` drives multi-touch through browser input, evaluates overlapping controls and manual/automatic modes. `manette.js`, `pavetactile.js`, `decompte.js`, `menus.js` and `langues.js` cover input-device, countdown and language journeys. Extend CS2's mobile reliability and online autofire tests with the same real actions.
- `navigation.js`, `traversee.js`, `bots.js`, `minicarte.js`, `killcam-reseau.js`, `saccades.js` and `gpu.js` offer comparative route, visibility, playback and timing scenarios. Pair these with CS2's existing replay/door, multimap/recovery, lag/room and soak probes. Bind results to a map/build/device and keep physical-phone evidence distinct from emulation.

## Distribution and language gates

`build.py` concatenates the 144 files in lexical order, prepends the shared filter from `api/_lib/filtre.js`, uses the HTML shell and `window.SOCLE`, and packages assets for lazy loading. It uses Three r147 and may load external PeerJS when no relay is configured. Do not import the global bundle into the CS2 runtime. Record exact source tree/path, symbol or data, dependencies, license, target caller and parity proof for each port. Port the pure `pchipSlope` directly. Its caller `keyM` returns a shared scratch array; give the caller an output buffer when sampling multiple hands or weapons in one frame. The full `updateViewmodel` reads renderer, game and weapon globals and needs an adapter. CS2 already consumes Riposte-derived recoil, pool, audio and math. Prefer extending the actual call sites.

Keep the MIT copyright notice for copied code. The local importer supplies replacement branding and hit sound, patches PWA scope/cache behavior, and omits original brand assets, music and Mixamo clips. The reference `NOTICE.md` and `assets/sfx/credits.json` distinguish per-asset rights; CC BY requires the relevant attribution. The reference tools can fetch or bake assets from other environments. Their presence does not supply those rights or missing files. Keep reference tools and developer URL modes outside production entry points. `00-i18n.js` can choose French from browser preferences or saved settings, and missing English keys display the French key. `05a-sfx.js` selects `voix_fr` or `voix_en` accordingly. The reference language checker deliberately skips scenery text. Retain interpolation/plural mechanics where appropriate, explicitly select English for CS3, and test a non-English browser plus imported/stale settings. Exercise visible text, native labels and dialogs, screen reader names, dynamic server reasons, CSS-generated content, canvas HUD/map labels, textures with instructions and spoken announcements. Keep stable IDs and user-authored names intact. A passing translation dictionary alone cannot certify the whole game.
