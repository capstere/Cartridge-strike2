## Proposed access design
Maintain current code/password path as legacy recovery during migration. Introduce separate opaque server-issued room authorization session, hashed or random token stored in server-side session store. HTTPS same-origin Secure HttpOnly SameSite cookie where compatible with WSS and CSRF protection; validate allowed Origin/Host and proof before reservation, never trust client-provided room ID/host. One-time or limited-lifetime scoped invite link containing high-entropy random code (not permanent password), exchange then remove from visible URL; ensure referrer/log redaction, rate limits, expiry and revocation. QR encodes same invite. Optional human short code maps to an expiring high-entropy invitation with attempt limits; not equivalent to global password. Stable family link contains alias only. Remember authorized device/session, provide revoke/sign out/forget. PWA same domain. Avoid permanent credentials in localStorage/URL. Guest solo remains one-click without network. 
## Account persistence
Official Riposte account and matchmaking backend absent; build own API with existing Express server or isolated service justified by review. Proposed SQLite transactional store outside versioned releases, check runtime/driver support Node 22–26 and backup support; if unavailable use proven alternative, not unprotected JSON passwords. Tables/versioned equivalents: users (id, normalized unique username, displayName, passwordHash, createdAt), sessions (hashed token, owner, scope, expiry/revoked), one-time recovery codes hashed, profile/settings/loadouts/outfits, match summaries and idempotent reward events. Store salted memory-hard password hash (scrypt/Argon2 with measured parameters and bounded concurrency), constant-time comparison, password length policy, server-side validation, rate limits per account/IP/global, generic auth failures, CSRF protection, rotation on login/password change and revoke all sessions. No mandatory email if one-time recovery codes are provided; explain lost-code limitations. Account deletion/export, minimal retention, no admin credentials in user store. Guest local progress separate and clearly labeled; do not trust claimed offline stats as online rewards. Server emits trusted XP and match stats with unique event/match IDs, transaction idempotency. Do not expose other users' private data.
## Match and public access
Host authoritative match choices; server-confirmed ready; immutable while playing. Room creation quotas/capacity, access isolation and independent simulation. Preserve bots/residents/settings, late join/reconnect/rematch, same map digest and contract. Public matches feature flag default off until account/admission, display name validation, moderation/report/block and capacity/security test pass; no fake public listing. Private family remains reachable when public disabled. Public lobby listing excludes private rooms and sensitive codes. Reject stale life/epoch and conflicting builds; validate normalized inputs, sequence numbers, flood/size and range. Inspect any full-state positional replication before promising UAV or spectator privacy.
