# Cold first sightline on Compact Arena

The original protocol-20 observer missed the SMG magazine withdrawal. Its first audio callback during the reload received a game time 0.867 s after the authoritative start and a previous time 1.467 s before it. That 2.333 s difference measures **client display simulation time between audio updates**. The native receipt contains neither a wall-clock render interval nor page visibility history. Its owner saw a 150 ms maximum in the same clock and delivered both magazine cues. [Original observer](../protocol-20/cold-observer.json) · [Original owner](../protocol-20/cold-owner.json)

On the network client, a snapshot moves display time forward to the latest authoritative simulation time. Between snapshots the client extrapolates up to 100 ms. The audio system stores its previous simulation time. Waking a background page, draining a blocked event loop or applying a late snapshot can therefore produce a large simulation delta. RenderBudget skips hidden documents and caps modal rendering at 10 Hz. Chromium background-throttling flags do not override the game's own budget. The two participants run in separate Chromium processes and native Wayland windows. Both processes reported document focus during the controlled experiments below. Exclusive operating-system focus cannot be inferred from that flag.

## Reproducing the first visible draw

The diagnostic uses the two normal multiplayer flows on the real local authority. Desktop selects Breacher in Wardrobe. Emulated touch and desktop take opposing seats. In matched fresh browser processes the authority places Breacher at the same authored navigation sightline and starts a single ordinary reload. This repeatable test action allows the observer window to stay in front. The original failing play used desktop fire and R. Both clients' render loops and Web Audio continue through the measured transition. Existing steady Rage and human-input checks remain separate.

The [two focus experiments and renderer-stage control](baseline.json) distinguish RAF delivery and renderer submission on the browser's monotonic clock from authoritative and displayed simulation time. The Pi 5 runs used Debian Chromium 156.0.8078.79 with native Wayland and Broadcom V3D 7.1.10.2, a single loopback room, protocol 20, build `5d3875bbbda009d9d1c63ce4d8e06227d5493745a1cc4c63c12935f5278a34fb`, two humans, zero bots and low graphics. Desktop was 896 × 504 CSS pixels, touch was 568 × 320 with mobile emulation, both at 0.75 device scale. The focused browser, episode length, instrumentation and SHA-256 of each raw trace are recorded with its result.

| Requested foreground | Desktop longest render | Touch observer longest render |
| --- | ---: | ---: |
| Desktop owner | 3,578 ms | 4,790 ms |
| Touch observer | 3,477 ms | 5,014 ms |

Both focused conditions reproduced a visible, unpaused first render stall. At that render the observer showed the actual shotgun outfit, comprising 51 meshes, including 13 skinned meshes. Three's GPU counts went from 119 to 162 geometries, 45 to 57 textures and 53 to 56 programs. No diagnostic image export had occurred before that first long observer draw.

With a third fresh pair, the observer's real world pass took 5,219 ms and the longest RAF interval was 5,234 ms. WebGL program-log calls accounted for almost the entire main-thread wait. The longest individual call took 1,077 ms. These synchronous calls can wait for earlier queued GPU work, including a shader pipeline's first actual draw. They locate where JavaScript blocked. Texture submission calls alone took up to 4 ms in that run. The server polling measures when a Node timer could observe simulation progress. It does not measure authoritative tick execution cost or network round-trip time. The first two runs ended before a full post-stall RAF interval was always delivered, so their render durations are the reliable wall-clock metric.

Use the pinned checkout with the existing Playwright and server dependencies, a fresh private output directory per run and only one heavy Pi job at a time.

```sh
WAYLAND_DISPLAY=wayland-0 XDG_RUNTIME_DIR=/run/user/1000 FPS_NETWORK_ANGLE=gl-egl \
CS3_BONUS_EVIDENCE=/tmp/fresh-owner-sightline CS3_BONUS_RELOAD_CAPTURE=1 CS3_BONUS_COLD_FOCUS=owner \
node --import ./server/register-shared.mjs tools/online-bonuses-browser.mjs
```

Use a different output directory and `CS3_BONUS_COLD_FOCUS=observer` for the second condition. Physical-phone touch latency, display scanout and acoustic output timing require separate evidence.

## Native cold-render correction

The scored source is commit `bc5ad5395ba05c4dad0cc990107ef7a57e1751cc`, protocol 20, build `b9d7ad66c75286cc4f16aeeadb1208a348e40bc5f1f4015237aae8e6049ba8ab`. The original runtime is the protocol-20 build `5d3875bbbda009d9d1c63ce4d8e06227d5493745a1cc4c63c12935f5278a34fb`. The final network manifest covers 706 files. Source SHA-256s, raw trace digests, per-seat distributions, slow frame counts and admission intervals are in [native-comparisons.json](native-comparisons.json).

On the Raspberry Pi 5, the observer's first world pass had to submit a previously unseen skinned wardrobe and its material/light combinations. Texture initialization alone still took 4,708 ms at first sight. Resolving the program uniforms before play still took 5,173 ms. One real preparation draw recovered some gameplay frames and synchronously blocked loading for seconds. Drawing individual variants without the nested action light still left a 1,057 ms first-sight frame. Matching the actual light layout and draining each small draw asynchronously avoided that stall. The WebGL information-log calls show where the CPU waited for preceding GPU work. They do not distinguish driver shader linking, native pipeline specialization and work queued ahead of the query. The [experiment records](experiments.json) identify source revisions and provisional manifests.

`loadRoomWorld` passes the room roster and its existing abort signal into the renderer. During the existing neutral-daylight network preparation, `Renderer.prepareOperatorPrograms` uses the assigned public class from `handling.outfitId`, the live weapon and light layout, and a representative shipped skinned outfit when both starting actors wear issued uniforms. It submits 16 × 16 scissored draws of the real material/geometry combinations one group at a time, flushes its fence, and polls with zero GPU wait. Each submission restores the active target, viewport and scissor before yielding. The extra pass requires `KHR_parallel_shader_compile`. When the extension is absent the additional preparation is skipped. During this preparation each GPU wait checks for abort or context loss. Native timing on a backend without that extension remains unmeasured. The pass creates no private rig request. Actor animation, view weapon, authoritative state and full gameplay geometry follow their normal paths.

The renderer holds one independently owned material per GPU program, 17 on the measured low-tier path, so a wardrobe change can retire the original material. Other warm material registrations, generated equipment geometry and the temporary rig are released. Authored avatars now own their texture handles for the uniform pattern. They share the same cached image source. The previous Ghillie left one stale GL disposal listener on the pattern after a change to issued and map exit. The corrected Ghillie releases its garment handle, retains all 17 program IDs through the swap and releases those program owners when the map renderer exits. A second, independently live context kept its one listener and a usable GL texture. See [before](retired-camo-before.json) and [after](retired-camo-after.json).

### Reproduction

Use one Pi GPU job at a time. Start with the environment in the command above, a fresh output directory for each trial, and `CS3_BONUS_COLD_FOCUS=observer`. Add `CS3_BONUS_COLD_GATE=1 CS3_BONUS_COLD_TURN=1` for the ordinary Breacher first sight. Add `CS3_BONUS_COLD_OUTFIT=sniper CS3_BONUS_COLD_RETIRE=1` for an already-admitted Ghillie and the independent-context retirement test. Use `CS3_BONUS_COLD_OUTFIT=sniper CS3_BONUS_COLD_LATE=1` for an all-issued host admitting a Ghillie later. Omit the turn flag to reproduce the cross-arena relocation. Remove all cold flags to run the original strict warmed reload gate. The separate lifecycle command is `node --import ./server/register-shared.mjs tools/bonus-cold-cancel.mjs` with the same Wayland session and evidence directory. Reduce a raw trace with `python3 tools/bonus-cold-summary.py OUTPUT/cold-sightline.json`.

The all-issued host then admitted a late Ghillie without another preparation pass. Its first visible render returned in 193 ms, the longest render took 199 ms and the longest RAF interval was 237 ms. Both seats played both samples. The separate authority-relocation run returned its first observer render in 115 ms, with 66 ms maximum render and 85 ms maximum RAF interval. The original relocation control took 5,028 ms to first visible completion, its longest observer render was 4,981 ms and neither client dispatched the two magazine samples in the captured window. On an ordinary turn the player fired and reloaded after turning, so the original normal-turn capture did deliver both samples despite the earlier visibility stall.

The 25 ms Node sampler peaked at 35 ms during the original normal turn and 31 ms during the final Breacher turn. In the late-Ghillie and relocation runs the instrumented authority completed 390/295 fixed ticks. Execution p95 was 3.72/3.42 ms, maximum execution was 15.55/8.72 ms and zero ticks exceeded 16.67 ms. Scheduling intervals p95 were 31.72/19.33 ms, maxima were 34.57/34.94 ms, and four/one intervals exceeded 33.33 ms. A delayed browser WebSocket callback can include client main-thread stalls. This fixture does not instrument packet arrival at the network interface or separately establish RTT. The existing [ten-seat pressure check](../load.json) exercises a different traffic scenario.

The independent wardrobe review found the analogous first-person issue. The engine cached a built-in sleeve profile across renderers and its previous disposer released only the materials. The subsequent protocol-20 build `5958767871dd610dbbc6fae8d29504cd7b25357dc2cad800d0a8dce9c7b02029` at `527a03b7f2d4940622eeed4932b0151f557f712b` gives each game renderer its own built-in profile cache and each camouflaged sleeve its own disposable texture handle. Private character and role-override profiles return from their original owners before accessing this cache. The preceding timing table identifies the build that produced it.

One legacy warmed-only run on `b9d7ad66` stopped at the credited-kill fixture before either reload was attempted. The fixture had directly respawned actors outside the canonical fixed tick. That sequence permits private rewards tagged with the new life IDs to flush before projection of those IDs into the public actor state. The failing run captured both empty private views but did not retain the incoming packet tags to prove this ordering on that particular run. The fixture now projects its public life changes synchronously, matching the game's fixed-tick order. The authority's private delivery checks and the browser's reward, visual and audio assertions are unchanged.

The corrected strict warmed run passed on the sleeve build. Ordinary SMG reload used 1.800 s and Rage used 1.350 s. The owner/observer rendered 70/66 and 54/55 measured reload frames respectively, including the magazine contact, and both played the decoded removal and insertion sample in each mode. The first-person and observer frames from both modes were reviewed beside their previous protocol-20 captures. The operator, weapon pose and magazine contact remained recognizable in all four comparisons. The adaptive desktop render size varied between runs.

The final native wardrobe journey checked five distinct class portraits, independent garment texture handles, matching CPU tile pixels/sampling and matching kit colors in the actual deployed game. Both desktop and touch picker screenshots decode identically to the PR #59 references. In the deployed snapshots the sole changed region was the bottom-center killstreak HUD, covering 12,096 of 921,600 desktop pixels and 8,808 of 329,160 touch pixels. All pixels outside those rectangles, including the operators and sleeves, were identical. The [final profile gates](final-profile-gates.json) include the file digests, decoded-RGB comparison, exact build, source checksums, wardrobe values and weapon/reload receipts.

On the final sleeve build the visible Ghillie was replaced by issued through real seat projection, followed by a UI map change. Both views kept their 17 program IDs through replacement and released every owner at map exit. The retired world garment's GL disposal listeners went 1 → 0 → 0. The first-person sleeve, which remained reusable in that renderer's two-profile cache, went 1 → 1 → 0. The old renderer released both profiles. Each separate live WebGL context retained its single listener on the CPU tile and its valid GL texture. An initial diagnostic attempt completed the normal turn and wardrobe replacement, then tried to read the old player during the player-free map transition. The corrected probe records that state as null and the full native repeat passed. The five relevant character, equipment and reload suites passed 31/31 using the repository's module loader.
