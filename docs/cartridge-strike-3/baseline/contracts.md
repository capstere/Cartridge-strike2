# CS3-00 interface decisions

These decisions govern the first vertical slices. Keep CS2's single fixed-step simulation, Colyseus room authority, Three r180 renderer and private save formats. Implement each new field with its first real consumer and a regression test. The [integration matrix](../RIPOSTE_INTEGRATION_MATRIX.md) records its source implementation. Use the [media review](../RECORDING_REVIEW.md) for visual comparisons.

| Interface | Ownership and semantics | Compatibility and evidence |
| --- | --- | --- |
| Input and movement | Gameplay owns shared gait in moveActor. Backend owns wire validation, projection and replay restoration. Mobile-input keeps raw forward angle and radial distance before CS2 clamps its axis. Carry a sprint intent and one ordered slide-start edge; ordinary run and sneak retain their existing movement. Only an eligible forward grounded actor enters Rush. Normalize opposing/diagonal inputs. | Extend input.mjs, wireInput/INPUT_FIELDS, ActorState and copyPose together with build/config validation. Reproduce V4 on desktop and touch. Reconcile through doors and crouch clearance. Clear held and queued actions on life, epoch, pause and phase changes. Verify protocol-14 recovery with its matching CS2 release. |
| Ready-to-fire and animation | Authoritative fixed steps determine sprint recovery and the first legal shot. A short trigger edge during recovery keeps the original fireId, generation, weapon and aim sample within the permitted input/rewind window. Clear on expiry, equipment swap or invalidation. Never extend rewind to make stale shots hit. The spring, grip, near-wall pose and camera are presentation consumers. | Offline, prediction, replay and server must agree on readiness. Test a tap/release in one coalesced batch, lag, one ammo subtraction, one locally deduplicated sound/flash and one confirmation. Capture long gun and pistol separately, including V1 near-wall control. Compare the ref's spring and the turn/stride phases without importing renderer globals. |
| Event and per-life state | MatchId, round, actorId, lifeId, controlEpoch, eventId and authoritative tick identify confirmed events. A predicted cosmetic may reference the actionId, never independently generate damage, progression or a second confirmation cue. Reload uses server start/deadline and per-action duration. Streak eligibility consumes the confirmed death event with immutable source and effect-at-emission, once. | Scope radar and replay to eligible recipients, validate identity again at send, clear upon invalidation. Preserve current broad actor-replication threat model in documentation. Use fixed ticks for bonus duration, cap progression carry within a match, and keep Classic round visibility/respawn rules. |
| Map and saved content | Graphics owns stable source ID → reviewed LevelProject/capabilities. Compile client and server from one static definition. Each online entry specifies modes, bounds, surfaces, spawns, routes, void rules, and any dynamic blockers. Emit a new collision contract revision if semantics expand. AI owns layer-aware navigation once needed. | Keep floor5-prepared and compact-arena and the synthetic fixture. Read LevelProject v2 and accepted v1 via parseProject/migrateV1. Distinguish floors at identical X/Z. Preserve embedded character package v1, the cartridge-private-characters IndexedDB and existing rig/clip IDs. Keep local imports off the network. |
| Settings, classes and account data | English strings map stable semantic keys and parameters to visible, spoken and accessible messages. Control/action/level IDs are independent of labels. Preserve cartridge-settings and private level-preview compatibility. The frontend hands UI actions to game/room controllers and reads explicit phase/error/purchase results. | Swedish/French locale fixtures, existing save, denied/retry, Classic buy, map art and English VO. A guest can play offline on Pages. The Pi pilot session, invitation/family proof, optional account identity and reserved seat remain distinct. CS3-04 may use SQLite after exercising the target Node version and private backup/restore; a trusted match/actor/event key makes rewards idempotent. |
| Content closure and build identity | Lead owns generator/allowlist updates. New modules, dynamic imports, English catalog, texture/voice takes and lazy assets must reach the clean served build. Preserve furniture-editor/build and library dependencies. Keep the default literal CONTRACT readable by the old Pi operator tool. | CS2's shipped manifest contains 528 files and 59,025,743 bytes, including 230 furniture-editor entries. Independently request lazy routes; compare exact build, map and collision digests. Verify compiled Pages and Pi packages exclude review media, debug tools and secrets. |
| Release surfaces | Use the CS3 integration branch for feature work. main currently auto-publishes the Pages repository root. Release gates cover both the offline site and the Pi authority. Stage candidate output and separate state before changing either live surface. | The GitHub deployment for main 1a9dc3f and the dynamic Pages build identify the live publishing ref. Root PNG and ZIP HTTP checks reproduced current file exposure. Pi publicFiles is a separate HTTP boundary. Existing stage-release.sh physically copies the whole tree. |
